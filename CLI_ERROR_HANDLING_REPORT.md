# Справка по выполненной работе в Market Pulse

## Предыдущая работа: фильтрация инструментов

По требованиям Javadoc `InstrumentFilter` логика отбора оформлена отдельными реализациями общего интерфейса:

| Раньше | Теперь |
| --- | --- |
| `FilterFactory` возвращала лямбды для типа, тикера, валюты и цены | Возвращает `TypeFilter`, `TickerFilter`, `CurrencyFilter` или `PriceFilter` |
| При отсутствии критериев фабрика возвращала лямбду, всегда дающую `true` | Возвращает один экземпляр `AllInstrumentsFilter` |
| Сравнение цены выполнялось через `switch` | Каждый оператор `GE`, `LE`, `EQ` содержит свою логику сравнения |
| `--price` без `--price-op` мог остаться без фильтра | Неполный фильтр вызывает ошибку |
| Старый `NoOpFilter` дублировал отбор всех инструментов | Дублирующий класс удалён |

Критерии по-прежнему взаимоисключающие: при нескольких одновременно заданных фильтрах фабрика сообщает об ошибке. Эти изменения были отправлены в GitHub в pull request №3.

## Задача

Проверить команды `add`, `list`, `search` и обработать ошибки так, чтобы пользователь видел понятное сообщение вместо стека вызовов Java. Добавить собственный тип исключения и проверить результат на реальных сценариях запуска.

## Что было обнаружено

| Сценарий | Поведение до доработки |
| --- | --- |
| `add FUTURE XYZ Name USD` | `IllegalArgumentException` на английском и стек вызовов |
| `add STOCK " " Name USD` | Ошибка пустого тикера на английском и стек вызовов |
| `list --type STOCK --ticker A` | Сообщение о конфликте фильтров и стек вызовов |
| `list --price 10` | Сообщение о неполном фильтре и стек вызовов |
| Неверная валюта, оператор, число, пропущенный аргумент | Сообщения Picocli на английском |
| `--help` | Клиент советовал эту опцию, но считал её неизвестной |

## Что изменено

1. Добавлен `CliException` — собственный тип для ожидаемых ошибок команды. В нём сохраняется исходная причина, чтобы её можно было исследовать в коде.
2. Команды `add` и `list` преобразуют ошибки неверных пользовательских данных в `CliException`.
3. Добавлен `CliExceptionHandler`. Он различает ошибки разбора аргументов и ошибки выполнения:
   - при неверных аргументах выводит `Ошибка ввода: ...`, синтаксис команды и код завершения `2`;
   - при `CliException` выводит `Ошибка: ...` без стека вызовов и код `1`;
   - при неожиданной ошибке выводит общее сообщение и код `1`.
4. В `Main` один обработчик подключён ко всем командам. Метод `createCli` выделен отдельно, чтобы проверять клиент без вызова `System.exit`.
5. Добавлена рабочая справка `-h` / `--help` для основной команды и подкоманд.
6. Сообщения о неизвестном типе инструмента и пустом тикере переведены на русский. Комментарий в `InstrumentFactories` исправлен: фабрики регистрируются при загрузке классов, а не через `ServiceLoader`.
7. Код обработчика разбит на методы для отсутствующих аргументов, неизвестных параметров и неверных значений. Добавлены русские комментарии о важных решениях.
8. Команда `search` переписана простым условием: найденный инструмент даёт успешный код `0`, отсутствие результата — код `1`.

## Как проходит обработка ошибки

```text
Аргументы командной строки
        |
        +-- ошибка разбора Picocli --> CliExceptionHandler --> сообщение + справка, код 2
        |
        +-- команда add/list --> неверные данные --> CliException
                                              |
                                              +--> CliExceptionHandler --> сообщение, код 1
```

Например, `add FUTURE XYZ Name USD` теперь печатает:

```text
Ошибка: Неизвестный тип инструмента: FUTURE. Допустимые типы: STOCK, BOND, ETF
```

А `list --price-op GE --price abc` печатает сообщение о том, что для `--price` ожидается число, и показывает синтаксис команды.

## Проверки

Добавлены интеграционные тесты `MainCliTest`. Они запускают те же команды через Picocli, которые вводит пользователь, и проверяют коды завершения, текст ошибок и отсутствие стека вызовов.

Проверены справка, неверная валюта, неизвестный тип, конфликт фильтров, неполный фильтр цены, успешные команды и оба исхода поиска. Дополнительно вручную проверены пустой тикер, пропущенные аргументы, неизвестная команда и опция, неверный оператор и неверное число.

Результат `mvn test`: **6 тестов, 0 ошибок, 0 падений**. Проверка `git diff --check` также прошла.

## Особенность текущего проекта

`InstrumentRepository` создаётся заново при каждом запуске `Main`. Поэтому добавленный через `add` инструмент не появится в отдельном следующем запуске `list` или `search`. Это текущее поведение хранилища в памяти, не ошибка обработчика исключений.

Изменения выполнены в локальной ветке `cli-error-handling` и пока не отправлены в GitHub.
